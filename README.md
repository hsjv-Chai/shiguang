# 拾光 · Mac 照片归档

中文原生 Mac 应用：按拍摄年月与城市移动归档，批量校正拍摄时间，保存原片备份并支持撤销。

## 使用

双击 `dist/拾光.app`。选择照片文件夹，点击或 ⌘/⇧ 多选照片，通过工具栏生成归档或时间修改预览，检查后执行。

- **归档**：选择目标根目录，按 `年/月/城市/原文件名` 移动。名称冲突添加编号，不覆盖。预览只检查文件状态与目标路径，不读取全部照片内容；确认后同一文件系统内直接移动，以文件身份和状态检查变化；跨盘边复制边计算哈希，读回目标校验通过后再删除源文件。时间、地点缺失时归入“未知时间”“未知地点”。已在目标目录的照片跳过。
- **校时**：整体前后偏移、统一日期时间、仅替换日期。预览只检查文件状态并批量读取元数据，显示进度、支持取消；不计算完整哈希。确认后只读 RAW 仅检查身份和状态，待修改文件在备份时计算哈希、验证备份和临时修改结果，再提交。使用 EXIF 墙上时间计算，保留已有时区和小数秒，不推断未知时区。文件系统修改时间不作为拍摄时间。
- **地点**：可手动批量指定。GPS 识别首次询问联网许可，只将坐标交给 Apple 地理编码服务；串行、缓存并重试。手动地点不会被自动识别覆盖，也不写入照片 GPS。
- **恢复**：在操作历史继续未完成批次，或撤销。必须先撤销较新的文件操作，再撤销依赖同一文件的旧操作。外部修改、路径冲突会阻止恢复，不会强行覆盖。
- **备份**：默认位于 `~/Library/Application Support/PhotoArchive/Backups`，可在应用设置或修改预览中更改。旧备份留在原位置。操作历史允许主动清理已撤销批次的备份。

支持 JPEG、HEIC/HEIF、PNG、TIFF 以及常见 RAW（CR2/CR3、NEF、ARW、RAF、DNG 等）。RAW 仅写标准同名 `.xmp`，原片不修改。已有 XMP 中其他编辑标签会保留。

### Canon JPG + CR2 成组管理

- 同一文件夹中，同名的一个 JPG/JPEG 和一个 CR2 自动显示为一张照片，扩展名不区分大小写。缩略图优先使用 JPG，标记 `JPG + CR2`；搜索任一成员文件名均可找到整组。
- 拍摄时间优先采用有效 XMP，其次 CR2，再次 JPG；GPS 优先使用 CR2 的完整坐标，缺失时使用 JPG。详情列出每个成员及 XMP 的路径、大小，并提示成员时间差异。
- 归档时 JPG、CR2 与已有 XMP 一起移动，名称冲突时整组使用相同编号。校时时以组级时间计算一次，同步写入 JPG 和 XMP，CR2 原片不变。零偏移也会补齐尚未同步的 JPG 或 XMP。
- 选择、计数、地点设置、预览、历史和撤销均以照片组为单位。整组文件检查和备份通过后才开始修改，中断后可继续或撤销。
- 升级后在每个已添加的来源中点击“重新扫描当前来源”，旧的两条照片记录会合并。手动地点保留；双方手动地点不同时优先采用 CR2 的地点并提示。
- 已绑定成员或 XMP 暂时缺失时保留绑定并阻止整组操作；重新接入后扫描恢复。多个 JPEG、多个 XMP 或额外同名格式仍视为配套歧义。
- 本次自动配对仅覆盖 JPG/JPEG + CR2，不跨文件夹配对，不自动合并其他 RAW 格式。旧操作历史仍按原文件步骤恢复，完成后重新整理受影响的照片组。

第一版不接入 Apple「照片」图库、不处理视频或 Live Photo 配对，不进行云端同步或自动去重。

## 构建

要求 macOS 14+ 和 Apple Command Line Tools（`xcode-select --install`）。当前构建产物面向 Apple Silicon；在 Intel Mac 上可按同样步骤原生编译。

```sh
./scripts/build-runtime.sh  # 首次从官方源码编译内置 Perl，需要联网
./scripts/build-app.sh      # 编译 Release .app，并做本机 ad-hoc 签名
./scripts/test.sh           # 文件级集成验证，包括一万张扫描
```

已提供的 `Vendor/Perl` 和 `dist` 是本机构建产物，不提交到 Git。ExifTool 源码已内置。构建 `.app` 时会复制完整 Perl 运行时及 ExifTool，最终用户无需安装这些依赖。应用没有 Developer ID 公证，面向本机使用。

当前 Command Line Tools SDK 的 `@State` 同时存在新宏和属性包装器，本项目通过 `ViewState` 类型别名明确使用 macOS 14 兼容属性包装器。测试采用独立 Swift 验证程序，不依赖仅随完整 Xcode 提供的 XCTest。`scripts/test.sh '关键词'` 可筛选测试名称。

## 结构和持久化

- `Sources/PhotoCore`：SQLite 索引、ExifTool 元数据服务、递归扫描、归档计划、日志和备份恢复。同盘归档和校时中的只读 RAW 使用文件身份与状态快照；SHA-256 指纹用于跨盘复制校验、校时及旧历史恢复。
- `Sources/PhotoArchive`：SwiftUI 三栏界面、ImageIO 懒加载缩略图、地点服务和任务管理。
- `Tests/PhotoCoreTests`：独立临时目录中的真实元数据读写和故障注入验证，不操作用户照片。

SQLite 数据库在 `~/Library/Application Support/PhotoArchive/library.sqlite`，WAL + FULL 同步。操作先写日志再修改；时间写入先为整组完成完整备份及内容校验，再在同一文件系统的独立临时目录完成写入、读取验证和结果哈希；整组准备好后逐个原子替换，新建 XMP 禁止覆盖。同盘归档使用禁止覆盖的原子重命名，并同步目录；跨盘先准备整组临时副本，边复制边计算源内容 SHA-256，同步并完整读回目标校验，再提交目标并删除源文件。正常跨盘每个文件的主体内容只读源一次、读目标一次；权限、时间及扩展属性通过系统接口复制。复制和校验可分块取消，提交与删除按组边界停止；多个文件的整组移动不是原子事务。

重新启动不会自动重做有副作用的操作。历史中的中断批次由用户选择继续或撤销，根据已记录阶段、文件身份与状态或内容指纹核对状态。旧历史保持原有哈希恢复逻辑。扫描跳过隐藏文件、符号链接和软件包；断开的来源保留索引，以便重新接入后继续管理。

同盘归档及撤销不提供逐字节内容一致性证明。正常执行比较设备、文件标识、大小、纳秒级修改和变更时间；重命名与日志更新之间的恢复窗口按身份、大小和修改时间确认文件，因为重命名本身会改变变更时间。状态不符时保留文件并拒绝继续。中断后的跨盘副本重新验证，可能需要额外读取。

校时预览每批最多向 ExifTool 提交 128 个待写入文件，只读 RAW 不做完整内容扫描。正常执行在备份复制时读取一次待修改原文件的主体内容，后续修改从已验证备份构造工作副本；临时副本写入和校验仍有必要的数据读写，不能按同盘移动的速度估算。新校时日志的恢复和撤销重新验证备份及已修改文件，只读 RAW 继续使用状态检查。成员绑定未变化时直接更新已验证的索引信息，旧日志或绑定变化时使用兼容整理流程。

## 验证结果和边界

详见 `VALIDATION.md`。照片测试覆盖的是已列出的夹具及生成图像；RAW 缩略图由系统 ImageIO 支持程度决定，不支持时显示占位图。保留备份可以恢复原始文件字节，但不能承诺保持每种外部照片软件的所有缓存和显示习惯。

## 应用图标

图标采用 UI 同款苔绿 `#40614D`、暖白 `#F5F2EA` 与叠放相片，使用原创矢量形状。设计及资源位于 `assets/AppIcon/`：

- `AppIcon.svg`：1024 × 1024 可编辑矢量图，包含独立 `background`、`foreground` 分组。
- `AppIcon-1024.png`、`AppIcon-preview.png`：透明底母版及浅深背景下的多尺寸预览。
- `AppIcon.iconset/`、`AppIcon.icns`：macOS 传统图标，包含 16、32、128、256、512 点的 1× / 2× 资源。16、32 点版本减少阴影、取消前景旋转并放大光点，改善小尺寸辨识。

运行 `./scripts/generate-app-icon.sh` 可重新生成全部资源，使用 macOS 自带 Swift/AppKit/Core Graphics 和 `iconutil`，无需额外依赖。几何与颜色的生成源为 `scripts/generate-app-icon.swift`；调整设计时修改此文件，避免下次生成覆盖单独编辑的 SVG。`./scripts/build-app.sh` 会自动生成并嵌入图标，然后签名应用。

当前交付为兼容 macOS 14+ 的静态 `.icns`，圆角底板之外保留透明边距；不是 Icon Composer 的动态 Liquid Glass 资源。未来迁移时应从分层源文件重新导出满幅背景，并由新管线施加系统蒙版，避免双重圆角。
